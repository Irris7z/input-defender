# 危険挙動のローカルテスト

プロジェクトのルートで `npm run demo` を実行し、Chromeで次のURLを開きます。

**http://127.0.0.1:4173/attack-lab.html**

本物の個人情報は使わず、初期値のダミーを編集して試してください。HTMLファイルを直接開くと操作は無効です。本拡張の対象はHTTP(S)の通常ページです。

## 最初に試す操作

1. Input Defenderを読み込み、対象ページを再読み込みします。通知除外にこのローカル送信先を追加していた場合は解除します。
2. 「自動送信を開始」を押し、氏名欄などのダミーを編集します。
3. 入力から約350ミリ秒後、ページのテストコードが入力値を読み取って別ポートに送ります。
4. 拡張のページ内警告と「検知記録」を確認します。
5. 拡張を「要注意の送信を停止」に切り替え、再び編集します。ページの実行結果に送信が停止された旨が表示されます。
6. 「自動送信を停止」で自動送信を止めます。ページを離れた場合も停止します。

## 用意した挙動

| 操作 | サイト側で行うこと | 確認点 |
| --- | --- | --- |
| 入力中の自動送信 | 編集のたびにフォーム値を読み、少し遅れてFetchで送る | ユーザーの送信操作前の通信を検知するか。停止モードで止まるか |
| Fetch / XHR | 読み取ったフォーム値をPOSTする | 主要な通信手段の検知・停止 |
| Beacon | 読み取ったフォーム値を通知送信する | 検知・停止。ブラウザの受付成功は受信完了の証明ではない |
| 画像URL | 読み取ったフォーム値を画像リクエストのURLに埋める | ブラウザ側の通信観測。現在の拡張では停止対象外 |
| 送信先を改ざん | フォームの送信先を4173から4174へ差し替える | 送信前の構造変化と、送信先の表示 |
| フォーム送信 | 現在の送信先へブラウザ標準のPOSTを行う | 送信先の検知、停止モード、受信確認 |

入力直後の検知には実際に欄を編集してください。「ダミーに戻す」だけでは信頼された入力イベントは起きません。HTTPのため、同一送信先でも平文通信の警告が出ます。v0.1.1では複数の理由を同時に表示します。自動送信では「入力直後の外部送信（自動送信の疑い）」と「暗号化されない通信（HTTP）」、改ざんでは「フォーム送信先の変更」などが並びます。HTTP警告の直後でも、新しい理由はその場で反映されます。

通知カードは上からFATAL（紫）→ CRITICAL（赤）→ WARNING（黄）の順に積み重なります。フォーム送信先の変更はFATAL、入力直後の外部送信・通信はCRITICAL、HTTPや外部フォームはWARNINGです。同じ種類・元ページ・送信先の繰り返しは通知受信回数にまとめます。通知を閉じても監視と検知記録は残ります。

## 送信先とデータの扱い

- ページ: `http://127.0.0.1:4173`
- 別サイトの代わりとなる受信先: `http://127.0.0.1:4174`
- 両サーバーともループバックだけで待ち受けます。
- HTMLの送信先を固定し、CSPでも通信・画像・フォームの送信先を上記の端末内アドレスに限定しています。
- 受信サーバーは本文を解析・保存・ログ出力せず、読み捨ててから固定の受信確認を返します。画像URLの入力値もログに出しません。
- ページ内の実行ログにも入力値は出さず、処理結果だけを最大30件表示します。永続ストレージは使いません。
- **このHTMLには意図的に入力値を読み取るコードがあります。拡張本体にはありません。** 拡張用ZIPの対象は `extension/` だけであり、このテストページは含めません。

通常の `/` のデモは引き続き固定文字列のみを送ります。実際の入力値を送るテストは、この `attack-lab.html` に分けています。
